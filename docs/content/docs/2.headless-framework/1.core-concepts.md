# Core Concepts

Notiq is a **headless** framework. It does not dictate CSS classes, modal layouts, or toolbar designs. Instead, it provides reactive React hooks and an editor engine that seamlessly connects to your UI design system.

---

## 1. `useNotiq` / `useEditor` Hook

The `useNotiq` hook initializes the editor lifecycle, registers extensions, sets initial content, and binds reactive re-rendering listeners:

```tsx
import { useNotiq } from '@collabchron/notiq'
import { StarterKit } from '@collabchron/notiq/starter-kit'

export function MyEditor() {
  const editor = useNotiq({
    extensions: [StarterKit],
    content: '<p>Welcome to <strong>Notiq</strong>!</p>',
    editable: true,
    autofocus: 'end',
    onUpdate: ({ editor }) => {
      // Triggered whenever document content or selection changes
      console.log('JSON:', editor.getJSON())
    },
    onSelectionUpdate: ({ editor }) => {
      // Triggered when cursor moves or text is selected
    },
    onFocus: ({ editor, event }) => {
      // Triggered when editor gains focus
    },
    onBlur: ({ editor, event }) => {
      // Triggered when editor loses focus
    },
  })

  // Returns null while initializing or hydrating
  if (!editor) return null

  return (
    <div>
      <p>Is Bold Active? {editor.isActive('bold') ? 'Yes' : 'No'}</p>
    </div>
  )
}
```

## 2. Rendering Content with `NotiqContent`

To render the editable surface in your React DOM tree, pass the `editor` instance to `<NotiqContent />`:

```tsx
import { NotiqContent } from '@collabchron/notiq'

export function EditorView({ editor }) {
  return (
    <NotiqContent
      editor={editor}
      className="notiq-editor prose dark:prose-invert max-w-none focus:outline-none"
    />
  )
}
```

### Supported Props:

| Prop | Type | Description |
| :--- | :--- | :--- |
| `editor` | `NotiqEditor \| null` | The editor instance returned by `useNotiq` |
| `className` | `string` | Optional CSS classes applied to the root container |
| `style` | `React.CSSProperties` | Inline styles for the editor container |

## 3. Querying Active Formats (`editor.isActive`)

Building floating menus and bubble toolbars requires knowing whether marks or block nodes are active at the current cursor position:

```tsx
// Marks
const isBold = editor.isActive('bold')
const isItalic = editor.isActive('italic')
const isCode = editor.isActive('code')

// Headings with attributes
const isH1 = editor.isActive('heading', { level: 1 })
const isH2 = editor.isActive('heading', { level: 2 })

// Block Types
const isBulletList = editor.isActive('bulletList')
const isCallout = editor.isActive('callout')
const isCanvasNode = editor.isActive('canvasNode')
```

## 4. Atomic Transactions

Whenever you run commands, Notiq aggregates them into an atomic transaction. This guarantees:

1. **Single History Step**: An entire chain (e.g., select line + toggle heading + apply color) creates a single Undo/Redo step.
2. **Synchronous AST Consistency**: No intermediate states where DOM or selection becomes invalid.
3. **Optimized Layout Thrashing**: React and Lexical only re-paint once after the entire transaction commits.
