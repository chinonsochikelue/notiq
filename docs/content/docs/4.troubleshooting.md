# Troubleshooting

Common issues and resolutions when installing, configuring, or embedding Notiq in production web applications.

---

## 1. SSR & Next.js Hydration Mismatch

### Problem
When rendering `NotiqContent` in Next.js App Router Server Components, you may encounter:
```
Error: Hydration failed because the initial UI does not match what was rendered on the server.
```

### Solution
Rich text editors depend on browser APIs (`window`, `document`, `Selection`, `contenteditable`). Always mark editor components as client components with `'use client'` or load them dynamically with SSR disabled:

```tsx [EditorWrapper.tsx]
'use client'

import dynamic from 'next/dynamic'

export const Editor = dynamic(
  () => import('./Editor').then((mod) => mod.Editor),
  { ssr: false }
)
```

---

## 2. Peer Dependency Conflicts

### Problem
When installing with `pnpm` or `npm 7+`:
```
Conflicting peer dependency: react@19 vs react@18
```

### Solution
Notiq supports React 18, React 19, and Next.js 14/15/16. If you encounter peer dependency warnings, configure your `.npmrc`:

```ini [.npmrc]
auto-install-peers=true
legacy-peer-deps=true
```

---

## 3. WebGL / Canvas Acceleration

### Problem
Spatial canvas panning feels jittery when hosting more than 100 card nodes simultaneously.

### Solution
Enable CSS hardware acceleration on your canvas viewport container:

```css
.notiq-canvas-viewport {
  transform: translate3d(var(--pan-x), var(--pan-y), 0) scale(var(--zoom));
  will-change: transform;
  backface-visibility: hidden;
}
```
