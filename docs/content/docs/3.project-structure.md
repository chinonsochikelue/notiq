# Project Structure

Notiq is structured as a modern high-performance monorepo designed for granular tree-shaking, subpath exports, and strict type safety across diverse front-end stacks.

---

## 1. Directory Overview

Here is an architectural map of the Notiq workspace:

```bash

├── packages/

│   │   ├── src/
│   │   │   ├── editor.ts      # NotiqEditor core class
│   │   │   ├── chain.ts       # Chainable command dispatcher
│   │   │   ├── extension.ts   # Extension & Node lifecycle
│   │   │   └── types.ts       # Shared TypeScript definitions
│   │   └── package.json
│   │
│   ├── starter-kit/           # Turnkey document editor kit
│   │   ├── src/
```

## 2. Package Bundling & Subpath Exports

Notiq is distributed with dual ESM and CommonJS bundles, with exact TypeScript declaration maps:

| Subpath Import | Purpose | Bundle Size (Gzip) |
| :--- | :--- | :--- |
| `@collabchron/notiq` | Core editor engine & hooks (`useNotiq`, `NotiqContent`) | **12.4 KB** |
| `@collabchron/notiq/starter-kit` | Standard Markdown nodes, marks, and history stack | **6.8 KB** |
| `@collabchron/notiq/blocks-kit` | Notion-style callouts, columns, toggles, slash menu | **8.2 KB** |
| `@collabchron/notiq/canvas` | 2D infinite spatial canvas & bezier connectors | **9.1 KB** |
| `@collabchron/notiq/collab` | Yjs CRDT binding, remote cursors, awareness | **7.5 KB** |
| `@collabchron/notiq/ai` | AI copilot prompt bar & streaming token writer | **4.3 KB** |

## 3. Lexical Runtime Encapsulation

Notiq vendors and wraps `@lexical/react`, `lexical`, and `@lexical/utils` so you never have to configure raw Lexical listeners or manually manage `editor.update(() => {})` batch loops unless you desire low-level AST access.

::tip
You can still access the underlying native Lexical instance at any time via `editor.getNativeInstance()` without sacrificing Notiq's chainable commands.
::
