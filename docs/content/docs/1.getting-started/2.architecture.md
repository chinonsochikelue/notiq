# Engine Architecture

Notiq is designed from the ground up for extreme speed, immutability, and zero DOM corruption. This guide details how the layers fit together.

---

## 1. Architectural Layers

Notiq is structured as a modular four-tier architecture:

```
┌────────────────────────────────────────────────────────┐
│             UI / Headless Consumers (React)            │
│       useNotiq() • NotiqContent • Custom Toolbars      │
├────────────────────────────────────────────────────────┤
│           Notiq Fluent API & Extension Bus             │
│   editor.chain() • Extensions • Kits • Event Bus       │
├────────────────────────────────────────────────────────┤
│                 Lexical Core Engine                    │
│   Immutable AST • Reconciliation Loop • Text Nodes     │
├────────────────────────────────────────────────────────┤
│            Browser DOM / Canvas Viewport               │
│         contenteditable / Infinite 2D Transform        │
└────────────────────────────────────────────────────────┘
```

---

## 2. Why Lexical as the Runtime Engine?

Traditional rich text editors like ProseMirror, Slate, or Quill model documents using either direct DOM mutations or monolithic JSON state trees that re-parse large chunks of the DOM on every keystroke.

In contrast, **Meta's Lexical** introduces:

1. **Double-Buffered State Trees**: Every update occurs on a shadow "work-in-progress" AST tree (`EditorState`). The active tree remains completely immutable until reconciliation commits.
2. **Granular Node Diffing**: Lexical calculates dirty nodes and modifies *only* the specific DOM elements that changed, ensuring keystrokes execute in under **4ms**.
3. **Flawless Internationalization (IME)**: Full native support for Japanese, Chinese, Korean composition, and mobile touch keyboards where ProseMirror frequently loses selection or splits tokens.

## 3. The Notiq Fluent Abstraction Layer

Raw Lexical is extremely powerful, but its native API is verbose and requires manual node traversal, command listeners, and boilerplate closures:

```ts
// Raw Lexical (Verbose & imperative)
editor.update(() => {
  const selection = $getSelection()
  if ($isRangeSelection(selection)) {
    $setBlocksType(selection, () => $createHeadingNode('h1'))
  }
})
```

Notiq encapsulates this complexity behind a fluent, chainable API modeled after modern editor design:

```ts
// Notiq Fluent Chain (Declarative, chainable, atomic)
editor.chain().focus().toggleHeading({ level: 1 }).run()
```

Every command in the chain receives a transaction context, batches AST updates into a single atomic Lexical update, and executes side effects synchronously.

## 4. Extension Lifecycle

Extensions in Notiq follow a declarative lifecycle:

```ts
import { Extension } from '@collabchron/notiq'

export const CustomHighlight = Extension.create({
  name: 'customHighlight',

  addOptions() {
    return {
      color: '#facc15',
    }
  },

  addCommands() {
    return {
      setHighlight: (color) => ({ chain, lexicalEditor }) => {
        return chain().setFormat('highlight', { color })
      },
    }
  },

  addKeyboardShortcuts() {
    return {
      'Mod-Shift-h': () => this.editor.commands.setHighlight(),
    }
  },
})
```

When an extension is registered:
1. `onBeforeCreate`: Extension options are validated and defaults injected.
2. `onCreate`: Lexical nodes, transforms, and listeners are registered with the Lexical instance.
3. `onDestroy`: Event listeners and subscriptions are cleanly garbage-collected.

## 5. State Serialization

Notiq supports round-trip serialization between multiple document formats:

- **JSON AST**: Lossless Lexical node tree representation (`editor.getJSON()`).
- **Semantic HTML**: Clean, sanitized HTML string (`editor.getHTML()`).
- **Markdown**: GFM-compliant markdown with tables, callouts, and code blocks (`editor.getMarkdown()`).
- **Plain Text**: Stripped raw string output (`editor.getText()`).
